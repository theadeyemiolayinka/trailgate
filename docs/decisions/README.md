# Architecture decision records

ADRs record significant decisions: context, the decision, and consequences. One file per decision, named `NNNN-short-title.md`, with a status of `proposed`, `accepted`, `deprecated`, or `superseded by NNNN`.

A contract-changing decision follows the process in ADR 0002.

| ADR | Title | Status |
| --- | --- | --- |
| 0001 | Monorepo layout and tooling | accepted |
| 0002 | Protocol decision and versioning process | accepted |
| 0003 | Request proof mechanism: HTTP Message Signatures | accepted |
| 0004 | Grant representation and key binding | accepted |
| 0005 | Discovery location and endpoint origin rules | accepted |
| 0006 | Constraint model and spending semantics | accepted |
| 0007 | Consent flow shape | accepted |
| 0008 | Draft 0.1 errata: algorithm identifiers and Idempotency-Key | accepted |
| 0009 | Contract ratifications: receipts, status, revocation, idempotency, spend_window, error codes | accepted |
