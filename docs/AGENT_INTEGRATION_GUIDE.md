# Agent integration guide

How a developer connects an AI agent to a TrailGate site. Uses the
implemented surfaces only; host-specific notes are marked unverified where
applicable.

## The pieces

| Component | Role |
| --- | --- |
| `@trailgate/agent` | Client SDK: discovery (+ signature verification and key pinning), consent orchestration, PKCE redemption, signed requests, receipt verification, key custody ports |
| `trailgate` CLI | Human-operated entry point over the SDK; shares `.trailgate` state |
| `trailgate-mcp` | stdio MCP server exposing nine `trailgate.*` tools over the SDK; shares `.trailgate` state |
| `@trailgate/server` | Site-side enforcement: discovery, consent, grants, `protect()` pipeline, approvals, receipts, audit |
| `apps/claude-host` | Terminal host that lets a Claude model drive the same tools via the Anthropic messages API |

The model never implements cryptography. It picks tools and reads results;
all signing, verification, and grant handling live in the SDK.

## How the pieces relate

```
 model/runtime --> tool call --> trailgate-mcp or claude-host
                                    | (in-process)
                                AgentClient (@trailgate/agent)
                                    | signed HTTPS requests
                                ExampleShop (@trailgate/server protect())
                                    | consent page / audit / receipts
                                   human user
```

The same `.trailgate` state dir is shared by the CLI and `trailgate-mcp`,
so a key generated by one is used by the other and grants are visible to
both.

## MCP-compatible hosts

Config shape (adapt to your host's schema; the command, args, and env are
what matter):

```json
{
  "mcpServers": {
    "trailgate": {
      "command": "node",
      "args": ["<repo>/packages/mcp-adapter/dist/mcp.js"],
      "env": {
        "TRAILGATE_STATE_DIR": "<repo>/.trailgate",
        "NODE_EXTRA_CA_CERTS": "<repo>/apps/example-shop/dev-certs/ca.crt"
      }
    }
  }
}
```

- `command` must be a Node >= 22.18 binary.
- `TRAILGATE_STATE_DIR` may be any writable directory the host can reach.
- `NODE_EXTRA_CA_CERTS` is required for the ExampleShop dev CA; omit it for
  public hosts with real certificates.
- Restart the host (or reload its MCP servers) to pick up changes; confirm
  the tools are visible by looking for `trailgate.discover` in the tool
  list.

Tools: `trailgate.discover`, `trailgate.actions`, `trailgate.access`,
`trailgate.request`, `trailgate.status`, `trailgate.redeem`,
`trailgate.fetch`, `trailgate.grants`, `trailgate.revoke`.

Consent cannot be skipped: `trailgate.request` returns a `consentUrl` the
human must open; `wait: true` polls until the human decides. No tool
approves anything by itself, and the `beforeAction` gate lets the host
require an extra operator confirmation for mutating tools.

## Claude API (no MCP host)

`apps/claude-host` is a reference terminal host that calls the Anthropic
messages API directly and exposes the same nine tools, with the operator
confirming each mutating call in the terminal:

```sh
export ANTHROPIC_API_KEY=sk-ant-...   # required, never printed
export NODE_EXTRA_CA_CERTS=<repo>/apps/example-shop/dev-certs/ca.crt
cd apps/claude-host && pnpm start "check my cart on https://localhost:3443"
```

Status: implemented and typechecked; the live API call is untested in this
environment because no API key is available. Adjust `ANTHROPIC_MODEL` if
needed.

## Devin and other hosted agents

A hosted agent can only use this integration if its runtime can spawn or
reach the MCP server, run a CLI, or call an equivalent tool surface. A CLI
on your laptop is not automatically reachable by a hosted agent. Verified
paths today:

| Path | Status |
| --- | --- |
| MCP stdio server (`trailgate-mcp`) with a local MCP host | Implemented and tested (initialize, tools/list, tools/call exercised end to end over live TLS) |
| `trailgate` CLI | Implemented and tested over live TLS |
| claude-host (Anthropic API, terminal) | Implemented; live API call unverified here |
| Hosted agents (Devin etc.) | No verified path; requires the hosted runtime to support an MCP server it can spawn locally or a reachable remote endpoint |

Do not expose the local MCP server as a remote endpoint to satisfy a
hosted agent: remote transport, authentication, and network exposure are
separate, unbuilt requirements.

## Connecting to a site

Tell the agent a URL (`https://localhost:3443`); the SDK fetches
`/.well-known/trailgate`, validates it, verifies the
`trailgate-discovery-signature` when present, and pins the site's keys for
continuity. Then:

1. `trailgate.discover` -> capabilities, permissions, action catalog.
2. `trailgate.actions` -> intent mapping: each action's method, path,
   permission, and whether a stored grant covers it.
3. `trailgate.access` -> is there a usable local grant for the scope.
4. If not: `trailgate.request` -> `consentUrl` for the human.
5. `trailgate.fetch` -> signed requests; server enforces everything.
6. `trailgate.revoke` -> self-revocation over the signed endpoint.

Unsupported sites produce `tg.discovery.invalid` cleanly; there is no
fallback that bypasses the protocol.

## Agent instructions (copy-paste)

```
You have TrailGate tools for talking to websites that support the protocol.

Rules:
- Use trailgate.discover on a site's URL before assuming support. If it
  fails, say the site does not support TrailGate and stop.
- Use trailgate.actions to map the user's intent to an advertised action;
  use the action's method and path with trailgate.fetch.
- Use trailgate.access to check local grant coverage before acting. If it
  reports no_grant or insufficient_permission, call trailgate.request with
  the minimum permissions and give me the consentUrl verbatim; never
  approve anything yourself.
- Always pass an idempotencyKey for mutating trailgate.fetch calls, and
  never retry a purchase blindly after an ambiguous response: check
  trailgate.status or the action result first.
- Report tg.* error codes honestly. A denied action stays denied; do not
  retry it, rephrase it, or split it to evade limits.
- Never ask for my site password, and never claim an action worked unless
  the tool result confirms it.
- To remove the agent's access, use trailgate.revoke with the grant id.
```

Example task for a live demo:

```
Use TrailGate to connect to https://localhost:3443, list the products,
then check what is in my cart.
```
